## Armed initiation flow (edit, 2026-11-26)
- User's words: "when you identify an opportunity to have a discussion with Elizabeth and we're both in the same room then show me the button that I have to press to initiate and you can show her the button to initiate and then we can have that agent to agent over the air talk."
- Implementation (client only, no schema/action changes): the page derives "armed" from the polled session state (`active=true` set by the agent via `set_session`, page not yet live). While armed it shows one large button naming the peer ("Tap to begin with Elizabeth") and hides the room / say-something sections so nothing competes. On becoming armed it attempts `engine.start()` automatically once per arming (reset when disarmed); if the platform refuses without a gesture, the big button is the gesture. Immediately after the microphone opens — by either path — it runs the existing `soundTheRoom()` flow automatically and saves the analysis; the manual "Sound the room" control remains for re-sounding while live. The un-armed idle presentation is unchanged.

## Bare-minimum connector UI (edit, 2026-11-26)
- User's words: the owner never operates this Space — it is purely the agent's connector — so the page is reduced to the absolute bare minimum a human ever touches.

Client-only change; no schema or action changes.

## Separate listen / ping controls (edit, 2026-11-26)
- User's words: "It seems tapping stop and start both create like a burst of audio and both listen silently so I think you need a different button one to begin listening and another button to ping or perhaps you can ping randomly between three and seven seconds"
- Root cause: the old single Start button called `engine.start()` and then immediately `soundTheRoom()`, so beginning to listen always emitted a sounding burst; with only one toggle button, Start and Stop looked and behaved confusingly alike.
- Fix (client only, no schema/action changes): two clearly separated controls. (1) Listening: "Begin listening" opens the microphone ONLY — no sounding, no playback, silent; "Stop listening" closes the microphone ONLY, cancels any ping timer, and makes no sound. Auto-start on agent arming is also silent now. (2) Ping: a distinct amber "Ping now" button (disabled until listening) that is the only on-demand sound — it calls the new `EarEngine.ping()` which plays one `sounding_burst()`, captures its echo into `soundingSamples`/`lastAnalysis`, and the page saves that reading via the existing `save_analysis` action (tagged `source: "ping"`). An "Auto-ping" switch alongside it, when on and listening, pings on a random 3–7 s timer (3,000 + random 0–4,000 ms, rescheduled after each ping, skipped while a queued message is speaking, cancelled on stop/disarm/unmount). Queued-message playback via `speak()` is unchanged and remains agent-driven.

## Single toggle UI (edit, 2026-11-26)
- User's words: "just one button or a toggle on and off that's it no captions description title container blah blah blah nothing just a very simple toggle switch on and off and when we do on it sends a heartbeat every three to seven seconds"
- Fix (client only, no schema/action changes): page reduced to ONE control — a large toggle switch (role=switch, aria-label "Ear on/off", knob labelled ON/OFF). Removed: title, status line, peer label, all section headings, explanatory copy, the separate Ping button, the Auto-ping switch, ping counts/timestamps, and all card containers. Toggling ON calls `engine.start()` (silent) and starts the heartbeat automatically — `engine.ping()` on a jittered 1–3 s timer (1,000 + random 0–2,000 ms; the user refined the original 3–7 s interval: "you don't have to do the three to seven seconds. If it's a very small thing, it can be done more frequent" — the heartbeat burst is very small, so it beats faster; rescheduled after each ping, skipped while a queued message is speaking, listen-before-talk inside `engine.ping()` unchanged, each ping's room reading saved via `save_analysis` tagged `source: "ping"`), and syncs the session via `set_session(active=true)`. Toggling OFF cancels the heartbeat timer, calls `engine.stop()`, and syncs `set_session(active=false)`. Agent arming still auto-starts listening once per arming and agent disarm still stops it, with the toggle reflecting the live state. Queued-message playback, decode/reporting, and all server actions are unchanged. A microphone/speech error still surfaces as a small alert so a failed start is not silent.

## Long-term data behavior
- **Refresh policy**: no scheduled refresh. The page polls `get_state` every ~2 s while open (session state, outbox, transcript tail, room analysis). The owning agent reads new incoming messages on demand via `get_inbox`.
- **Growth**: transcript, inbox and outbox rows are append-only and small (short text turns, capped per the codec's segment caps); no pruning in this build.
- **Ordering**: transcript shown oldest→newest by id; inbox delivered oldest-first; outbox spoken oldest-first (FIFO).
- **Time semantics**: `created_at` timestamps are creation instants rendered viewer-local; message times in the transcript are the viewer's local time.

## Rejected approaches
- **Tried**: Worker-based encode/decode service as the meeting point (original stage-2 shape in the requirements doc)
  **Why rejected**: superseded by the user's own architecture amendment (Nov 26, ~22:03, recorded in the same doc): for the same-room case each house's Space embeds the codec and the air carries only the conversation. The Worker is demoted to an optional later relay and is not built here.
- **Tried**: hand-writing or simplifying a codec in the page
  **Why rejected**: the brief requires embedding the conformance-proven module whole; a rewrite would void the cross-implementation proofs. Only the single specified `analyze_channel` hardening patch is applied.
